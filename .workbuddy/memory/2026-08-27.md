## 修复「点击按钮」等指令无反应（NLP 解析大修）

用户反馈「输入点击按钮离线识别没有反应」，实测复现两类根因：

### 根因 1：NLP 正则非贪婪 + 次数必填导致解析失败
- 点击规则 `(?:\s*(\d+)\s*次?)` 的 `(\d+)` 是**必填** → 「点击按钮」「点击登录」「点一下开始」全部匹配失败 → 掉进 unknown
- 多个规则用 `(.+?)` 非贪婪且无锚定 → 「搜索人工智能」只解析出 value="人"、「悬停在登录按钮上」只取 1 个字
- 输入语序 B 的 value 非贪婪 → 「输入你好到搜索框」value 只剩"你"

### 根因 2：unknown 动作被静默过滤 → UI 显示"成功 0 失败 0"（看起来完全没反应）
- `parseToActions` 里 `.filter((a) => a.type !== 'unknown')` 把无法解析的指令悄悄丢掉

### 修法（`src/pages/Agent/UniversalPageAgent.jsx`）
1. 新增 `cleanTarget`（去引号）+ `parseClickTarget`（剥离"2次"次数标记与"按钮/链接"等元素后缀，保留整体为后缀的情况如"点击按钮"）
2. 点击/搜索/悬停/输入/选择/勾选规则 `(.+?)` → `(.+)` 贪婪；点击次数整体可选
3. 输入语序 B 拆成 B1（带"到"）+ B2（无目标自动定位）
4. **悬停/按键(press)规则前置**到点击前，避免"悬停…按…""按下回车"被点击规则抢走
5. **back/forward 规则前置**到滚动前，避免「返回上一页」被滚动规则的"上一页"抢走
6. `parseToActions` 不再过滤 unknown；execute 增加 unknown case → 明确报错「无法理解指令「XX」，试试「点击XX」「输入XX」「跳转到XX」」
7. 新增 `normalizeVoiceText`：繁体→简体 + whisper-tiny 误识别修正（電機→点击、按鈕→按钮、滾動→滚动…），语音 onResult 先归一化再执行

## Embed 页面换方案：放弃 HTML 改写代理，改双模式预览

## Embed 修复：检测"可内嵌"但实际 iframe 403

用户反馈「检测可以内嵌，但是实际打开是 403 forbidden」。

### 根因（两处）
1. **探测请求是裸请求（无 Referer）**：`/__frame-check` 只带 UA/Accept，而浏览器 iframe 加载目标时会带 `Referer: http://localhost:5173/`。很多项目后端有 **Referer/防盗链校验**（Nginx valid_referers、Spring Security、WAF）——裸请求放行 → 检测判"允许内嵌"，iframe 带外站 Referer 被服务器 403 拒绝
2. **allowsFrame 只看 XFO/CSP，不看 HTTP 状态码**：服务器返回 403/401/5xx 照样报"允许内嵌"

### 修复
- `vite.config.js` `embedHelpers()`：探测请求头加 `referer: 'http://localhost:5173/'` **模拟 iframe 上下文**；判定改为 `statusBlocked = status>=400`（先看状态码）→ `frameBlocked`（XFO/CSP 不含 * 或 localhost）→ `allowsFrame = !statusBlocked && !frameBlocked`；返回 `status/statusBlocked/frameBlocked/contentType`
- `Embed/index.jsx`：提示条细分 4 态——探测失败(红) / statusBlocked(红,403 提示防盗链·Referer·IP 限制,401 提示需登录) / 禁止嵌套(黄,含 XFO/CSP 详情) / 允许(绿,附带 HTTP 状态码)；iframe 下方提示条同步覆盖 statusBlocked（err 红）
- **附带修复 normalizeUrl**：`localhost`/`127.0.0.1` 默认补 `http://`（本地 dev server 基本是 http，默认 https 会导致 iframe/探测 SSL 全失败）

### 验证与坑
- 本地起 mock-referer-server.js（:4567）：无 Referer→200、带本站 Referer→403，完美复现用户场景
- e2e-embed-403.js 12/12 PASS：403 项目显示红色"服务器拒绝访问(HTTP 403)"不误报允许、iframe 模式提示条 err、example.com 仍绿+HTTP 200、无 console error
- **坑**：e2e 故意加载 403 项目会产生预期的 console error（`Failed to load resource: 403`）→ 场景切换时 `errors.length = 0` 清零再断言后续区间
- 回归：e2e-embed-new.js 13/13、全站 8 路由 OK、lint 零错误；截图 embed-403-iframe.png / embed-403-ok.png

用户内嵌 localhost:9001 项目时报 `SecurityError: Failed to read a named property 'href' from 'Location': Blocked a frame with origin "http://localhost:9001" from accessing a cross-origin frame. at scheduler.development.js:217`

### 结论（实测验证）
- **不是我们页面的 bug**：React 的 scheduler.development.js:217 只是调度循环起点（`localSetImmediate(performWorkUntilDeadline)`），**scheduler 本身从不访问 location**；真正访问跨域 `window.top.location.href`/`parent.location.href` 的是**被内嵌站点自身代码**（防嵌入/防钓鱼检测、埋点 SDK、或 React DevTools 扩展 hook 在跨域 iframe 的已知行为），错误栈归到调度点是异步栈的假象
- **跨域 iframe 错误不冒泡到父页面**：实测 mock-crossorigin-app.js（:4568）+ e2e-crossorigin.js 5/5 PASS——iframe 内部抛 SecurityError 时父页面（Embed）零 pageerror/console error、UI 正常、被嵌应用也继续运行
- **Web 层面无法从父页面修复/拦截**（同源策略双向）：sandbox/referrerpolicy 属性均无效
- 处理建议：该站点用「新窗口预览」；若是自有项目，搜代码里 `window.top`/`parent.location` 访问点；若是 React DevTools 扩展噪音，关扩展/无痕/新窗口即消失
