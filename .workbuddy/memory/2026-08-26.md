## 语音识别不可用排查与根治（双引擎：在线 + 本地 Whisper 离线）

### 根因
- Chrome 中文在线识别依赖 `speech.googleapis.com`（Google 服务），国内网络不可达（curl 返回 000），表现为"正在聆听但永远无结果"。
- 解法：新增本地离线识别引擎，语音不出本机。

### 本地离线识别（Whisper）踩坑记录（重要）
1. **模型来源**：`Xenova/whisper-tiny`（量化约 40MB）。hf-mirror.com 有 CORS 限制（`access-control-allow-origin: https://hf-mirror.com`），浏览器跨域被拦 → 模型文件下载到 `public/models/` 同源托管，配 `env.allowLocalModels = true` + `env.allowRemoteModels = false`。
2. **下载必须 `curl -sL`**（带 -L 跟随重定向），否则存的是 "Temporary Redirect" 响应体（JSON 解析报错）。
3. **qdq bug（核心坑）**：`qdq_actions.cc:137 TransposeDQWeightsForMatMulNBits Missing required scale`。
   - 根因：transformers.js **4.2.0 把 onnxruntime-web `1.26.0-dev` 的 JS 打包进 dist**（改 node_modules 里的 onnxruntime-web 版本无效！），该 dev 版 wasm 对量化权重转置有回归 bug。
   - 解法：**降级 transformers.js 到 `3.8.1`**（打包 onnxruntime-web `1.22.0-dev.20250409`，无此 bug），API 与 v3.8.1 兼容：`env.localModelPath` / `env.allowLocalModels` / `env.allowRemoteModels` / `pipeline('automatic-speech-recognition', ...)` / `asr(pcm, { language:'chinese', task:'transcribe', sampling_rate:16000 })` / 输出 `output.text`。
4. **wasm 本地化**：v3.8.1 的 dist 自带配套 wasm（`ort-wasm-simd-threaded.jsep.mjs` + `.wasm`，21MB），默认 wasmPaths 指向 jsdelivr CDN → 复制到 `public/ort/`，在 hook 里配置 **`env.backends.onnx.wasm.wasmPaths = { mjs, wasm }`**（注意：v3 的配置路径是 `env.backends.onnx.wasm.wasmPaths`，**v4 才改为 `env.wasmPaths`**）。
5. **Vite 禁止 import public 文件**：transformers.js 动态 import `/ort/xxx.mjs?import` 时 Vite 返回 500（public 目录文件不能被源码 import）。解法：在 `vite.config.js` 加 `serveOrtAssets` 插件，`configureServer` 内直接 `server.middlewares.use(...)` 拦截 `/ort/` 返回原文件。**注意 Vite 8 中 configureServer 返回函数是无参 post-hook（`fn()` 调用），pre 中间件必须直接在 configureServer 里 use**。生产构建时 public/ 自动复制到 dist/，无需插件。
6. 生产构建会自动把 transformers.js 静态引用的 wasm 再打包一份到 `dist/assets/`（约 21MB 冗余，功能无影响）。

### 验证
- e2e（playwright + 虚拟麦克风）跑通：模型 200 → wasm 本地加载 200 → 模型 100% → 录音 2.5s → 文本框输出识别文字。
- 生产 `vite build` + `vite preview` 下 `/ort/`、`/models/` 资源全部 200 且 MIME 正确。
- 依赖版本：`@huggingface/transformers@^3.8.1`（package.json 已固定）。

## UniversalPageAgent 功能增强（文字指令 / 快捷键 / 语音控制）

三个用户痛点全部解决并 e2e 验证通过（`/tmp/pwtest/e2e-agent.js`）：

### 1. NLP 指令解析重写（`src/pages/Agent/UniversalPageAgent.jsx` 的 NLP_RULES）
- **输入规则拆成两个顺序变体**（修复"输入你好到搜索框"贪婪匹配 bug）：A. `在XX输入YY`；B. `输入YY(到XX)?`，target 可选，无 target 时自动定位第一个可见输入框。
- 新增导航规则（跳转到/前往/打开/去 → navigate，支持绝对 URL / React Router 路由 / 页面内链接）、双击规则（先于单击）、滚动表达式（向上/下滚/下一页等）。
- **兼容繁体/谐音**：e2e 中语音识别出"向下滾动"（繁体滾）仍被正确解析——规则用字面"向下"+"滚动/滾动"双写法匹配。

### 2. 执行器与 Direct Bridge 增强
- `SimplePageAgent.execute` 新增 navigate/search/press/select/check/wait case。
- `createDirectBridge(router)` 新增：`isVisible()`（computed style + rect 过滤隐藏元素）、`findFirstVisibleInput()`、`navigate()`（绝对 URL→Router→页面链接→前缀路由四级回退）、`search()`、`press()`、`select()`、`check()`、`wait()`；scroll 改 window.scrollBy。
- **关键**：`bridge` 需用 `useMemo` 包裹（依赖 `[mode, router, sendBridgeMessage]`），否则触发 useCallback 依赖告警。

### 3. 语音控制（复用 useWhisperRecorder）
- 组件内 `onResult`：识别文本填入输入框 → 120ms 后自动 `runTask(text)` → 自动执行跳转/点击/滚动。
- **注意：`runTask` 开头 `setInputValue('')` 会清空输入框**——e2e 断言不能靠读输入框判断语音是否成功，要看历史条目 / statusMsg（"完成：成功 x，失败 y"）。

### 4. 全局快捷键（`src/components/GlobalAgent/index.jsx`）
- PageUp/PageDown 滚 ±90vh；Home/End 到顶/底；Ctrl/Cmd+↑↓ 滚 ±50vh；Ctrl/Cmd+Alt+←→ history 前进后退；`isTyping()`（焦点在输入框/textarea/contentEditable）时跳过快捷键。

### 5. e2e 语音测试的关键坑（重要）
- headless Chrome 默认虚拟麦克风是 beep 音，Whisper 识别为空文本 → 需要注入真实语音：`--use-file-for-fake-audio-capture=<wav>`。
- 生成中文语音 WAV：`say -v Tingting -r 140 --data-format=LEI16@22050 -o speech.wav "向下滚动"`（afconvert 转 aiff 会报 `ExtAudioFileCreateWithURL failed ('typ?')`，直接用 say 的 `--data-format` 输出最省事）。
- whisper-tiny 对 TTS 识别精度有限："跳转到首页"→"跳转到手叶"；换"向下滚动"→"向下滾动"（可正确执行）。真实人声效果会更好。
